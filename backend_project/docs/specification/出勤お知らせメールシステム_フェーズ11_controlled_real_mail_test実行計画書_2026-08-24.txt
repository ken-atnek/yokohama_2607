9. 送信前DB確認SQL
==================================================

以下は実行計画用のread-only SQLである。
本書作成時点では実行しない。

個人情報を出力しないため、メールアドレスはSHA-256 hashで照合・表示する。
実行時は、実メールアドレス全文ではなく事前計算したhashをセッション変数として指定する。

SET @expected_recipient_sha256 = '事前計算したlowercase emailのSHA-256 hex';
SET @test_cast_id = 12345;
SET @allowed_shop_ids_csv = 'actual config empty_mail.allowed_shop_ids をカンマ区切りで指定';
SET @test_shop_id = 'SQL-4Aでpass確認したshop_id';

`@allowed_shop_ids_csv` は、production actual config の `empty_mail.allowed_shop_ids` をread-only確認して設定する。
ConfigLoader上の許可可能値は `yh-dandy` / `yh-clubd` / `yh-mrd` だが、実行時はactual config値を正とし、推測で補完しない。
`@test_shop_id` は SQL-4A の `shop_id` が `pass` であることを確認した後、その値を指定する。

期待値:

- generation前: SQL-1 eligible mail unit count = 0
- generation前: SQL-2 schedule_update eligible group count = 0
- generation前: SQL-3 stale mail unit count = 0
- generation前: SQL-4A target cast validation = pass
- generation前: SQL-4B active suppression count = 0
- generation前: SQL-4 test subscriber active / target subscription non-active
- generation前: SQL-5 target subscription_added eligible count = 0
- generation後: SQL-1 eligible mail unit count = 1
- generation後: SQL-2 schedule_update eligible group count = 0
- generation後: SQL-3 stale mail unit count = 0
- generation後: SQL-5 target subscription_added eligible count = 1
- generation後: SQL-5 detail queryで取得した delivery_id を target_delivery_id として記録

SQL-1 eligible mail unit list/count

SELECT
    COUNT(*) AS eligible_mail_unit_count
FROM (
    SELECT d.delivery_id AS representative_delivery_id
    FROM t_notification_delivery d
    WHERE d.mail_type <> 'schedule_update'
      AND d.status IN ('queued', 'deferred')
      AND d.available_at <= UTC_TIMESTAMP(6)
    UNION ALL
    SELECT MIN(g.delivery_id) AS representative_delivery_id
    FROM t_notification_delivery e
    INNER JOIN t_notification_delivery g
        ON g.message_group_key = e.message_group_key
       AND g.mail_type = 'schedule_update'
    WHERE e.mail_type = 'schedule_update'
      AND e.message_group_key IS NOT NULL
      AND e.status IN ('queued', 'deferred')
      AND e.available_at <= UTC_TIMESTAMP(6)
    GROUP BY e.message_group_key
) eligible_units;

SELECT
    eligible_units.representative_delivery_id,
    eligible_units.mail_type,
    eligible_units.subscriber_id,
    eligible_units.subscription_id,
    eligible_units.recipient_sha256,
    eligible_units.status_summary,
    eligible_units.available_at,
    eligible_units.delivery_row_count,
    eligible_units.eligible_row_count
FROM (
    SELECT
        d.delivery_id AS representative_delivery_id,
        d.mail_type,
        d.subscriber_id,
        d.subscription_id,
        SHA2(LOWER(d.recipient_email_snapshot), 256) AS recipient_sha256,
        d.status AS status_summary,
        d.available_at,
        1 AS delivery_row_count,
        1 AS eligible_row_count
    FROM t_notification_delivery d
    WHERE d.mail_type <> 'schedule_update'
      AND d.status IN ('queued', 'deferred')
      AND d.available_at <= UTC_TIMESTAMP(6)
    UNION ALL
    SELECT
        MIN(g.delivery_id) AS representative_delivery_id,
        'schedule_update' AS mail_type,
        MIN(g.subscriber_id) AS subscriber_id,
        MIN(g.subscription_id) AS subscription_id,
        SHA2(LOWER(MIN(g.recipient_email_snapshot)), 256) AS recipient_sha256,
        GROUP_CONCAT(DISTINCT g.status ORDER BY g.status SEPARATOR ',') AS status_summary,
        MIN(g.available_at) AS available_at,
        COUNT(DISTINCT g.delivery_id) AS delivery_row_count,
        COUNT(DISTINCT e.delivery_id) AS eligible_row_count
    FROM t_notification_delivery e
    INNER JOIN t_notification_delivery g
        ON g.message_group_key = e.message_group_key
       AND g.mail_type = 'schedule_update'
    WHERE e.mail_type = 'schedule_update'
      AND e.message_group_key IS NOT NULL
      AND e.status IN ('queued', 'deferred')
      AND e.available_at <= UTC_TIMESTAMP(6)
    GROUP BY e.message_group_key
) eligible_units
ORDER BY eligible_units.representative_delivery_id;

SQL-4A target cast validation

実装照合:

- EmptyMailRegistrationService: girls()->findById($castId)
- GirlRepository: t_girl_master2.g_id / name / att_shop / view
- 公開判定: view = '1'
- 店舗判定: TRIM(att_shop) != ''
- 許可店舗判定: att_shop IN actual config empty_mail.allowed_shop_ids
- rejection reason: cast_not_found / cast_hidden / shop_missing / shop_not_allowed
- その他generation blocker: rate_limit_global / rate_limit_email / rate_limit_email_cast / suppressed / subscriber_suppressed / already_active / admin_paused / invalid_subscription_state

SELECT
    @test_cast_id AS requested_cast_id,
    g.g_id AS cast_id,
    g.view AS cast_view,
    TRIM(COALESCE(g.att_shop, '')) AS shop_id,
    CASE
        WHEN g.g_id IS NULL THEN 'cast_not_found'
        WHEN CAST(g.view AS CHAR) <> '1' THEN 'cast_hidden'
        WHEN TRIM(COALESCE(g.att_shop, '')) = '' THEN 'shop_missing'
        WHEN FIND_IN_SET(TRIM(g.att_shop), @allowed_shop_ids_csv) = 0 THEN 'shop_not_allowed'
        ELSE 'pass'
    END AS empty_mail_cast_validation
FROM (SELECT @test_cast_id AS cast_id) target
LEFT JOIN t_girl_master2 g
    ON g.g_id = target.cast_id
LIMIT 1;

2. detail queryの `delivery_id` を1件だけ取得する
3. その値を `target_delivery_id` として実行ログに記録する
4. 以後の送信後DB確認は、再検索だけに頼らず `delivery_id = target_delivery_id` で追跡する

これはspecific delivery送信機能ではない。
send-deliveries.phpにはdelivery_id指定機能を追加しない。
送信処理そのものは従来どおりeligible mail unit全体を対象とする。

SQL-6 target_delivery_id tracking

SET @target_delivery_id = 0;

`@target_delivery_id` には、SQL-5 detail queryで確定したdelivery_idを実行時に指定する。

SELECT
    d.delivery_id,
    d.subscriber_id,
    d.subscription_id,
    sub.shop_id,
    sub.cast_id,
    SHA2(LOWER(d.recipient_email_snapshot), 256) AS recipient_sha256,
    d.mail_type,
    d.status,
    d.available_at,
    d.attempt_count,
    d.max_attempts,
    d.template_key,
    d.template_version,
    d.sent_at,
    d.failed_at,
    d.deferred_at,
    d.last_error_code,
    d.provider_message_id,
    d.updated_at
FROM t_notification_delivery d
INNER JOIN t_notification_subscription sub
    ON sub.subscription_id = d.subscription_id
WHERE d.delivery_id = @target_delivery_id
  AND d.mail_type = 'subscription_added'
  AND sub.shop_id = @test_shop_id
  AND sub.cast_id = @test_cast_id
  AND SHA2(LOWER(d.recipient_email_snapshot), 256) = @expected_recipient_sha256
LIMIT 1;

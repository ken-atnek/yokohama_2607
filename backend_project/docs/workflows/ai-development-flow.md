# バックエンドAI開発フロー

## 目的

公開サイト連携バックエンドの調査、実装、レビュー、修正を安全に進めるための標準工程です。

PHP / SQL / DB / SESSION / API / JSON / cron / メール処理は副作用が大きいため、調査と実装を分離します。

## Claudeレビューの2段階

Claudeレビューは、初回第三者レビューと修正後再レビューを区別します。

| 種別 | 実施タイミング | 目的 |
| --- | --- | --- |
| 初回第三者レビュー | Codex初回実装後 | 仕様矛盾、既存処理への影響、セキュリティ、DB/API/SESSION/メール/CLIなどを第三者視点で確認する |
| 修正後再レビュー | Codexが採用項目を修正し、構文確認・テスト・git diff確認を終えた後 | 採用した指摘が正しく直っているか、修正で新しい不具合を入れていないかを確認する |

修正後再レビューは、初回レビューと同じ範囲を最初から見直す工程ではありません。

## 修正後再レビューで共有するもの

修正後Claude再レビューが必要と判断した場合、プロンプトには必要に応じて以下を含めます。

- 初回Claudeレビューの指摘
- ChatGPTによる指摘整理
- Codexによる事実確認
- Codexの採用 / 保留 / 対応不要判断
- 採用した指摘
- Codexの修正内容
- 対象ファイル
- 修正後git diff
- 構文確認・テスト結果

確認範囲は、前回指摘、Codex採否、採用項目、修正内容、修正後diff、確認結果に限定します。

## 修正後再レビューで新しい指摘が出た場合

新しい指摘は、すぐに実装せず、以下の順で扱います。

1. ChatGPTで指摘内容、根拠、優先度、依頼範囲との関係を整理する
2. Codexが実リポジトリで事実確認する
3. Codexが採用 / 保留 / 対応不要を判断する

採用候補:

- 今回の修正で新しく入った不具合
- 初回指摘の修正漏れ
- 確定仕様違反
- セキュリティ問題
- Critical / High相当の問題

保留候補:

- 既存不具合の可能性が高い
- 今回依頼の範囲外
- 仕様判断が必要
- DBまたは本番環境確認が必要

対応不要候補:

- リファクタリング提案
- コーディングスタイルの好み
- 仕様上の問題が確認できない
- 誤指摘または過剰提案

新規指摘のうち、今回追加対応するのは採用候補の中でも今回対応必須の重大項目に限定します。既存問題、依頼範囲外、大規模リファクタリング案、コーディングスタイルの好み、仕様上問題のない提案、過剰提案は原則として今回の追加修正対象にせず、必要に応じてREVIEW_FIX_TRACKERへ保留として記録します。

追加修正を行った場合は、ChatGPT最終回答・diffレビューへ進む前に、Codexで構文確認、必要なテスト、git diff再確認を行います。

## 無限ループ防止

標準工程では、Claude Codeによるレビューは初回第三者レビューと修正後再レビューの最大2段階までとします。

修正後再レビューを受けて追加修正した場合も、機械的な3回目のClaudeレビューは標準工程に追加しません。追加の再レビューは、重大な未解決問題が残る場合のみ別途検討します。

## 修正後再レビューの省略と必須目安

コメント、typo、文言、ドキュメントのみで挙動に影響しない修正は、理由を残したうえで修正後再レビューを省略できます。

以下を含む修正では、原則として修正後Claude再レビューを実施します。出勤お知らせメール等のPHP / API / DB / 認証 / メール / cron関連実装も、原則として再レビュー対象です。

- PHPロジック
- SQL / DB処理
- 認証、認可、SESSION、CSRF
- API
- メール
- cron / CLI
- 個人情報、token、ファイル操作
- JSON生成
- 複数ファイルにまたがる修正
- セキュリティに関わる修正

## Codex調査で確認するもの

- 対象仕様書
- 既存コード
- 呼び出し元
- 呼び出し先
- DBテーブル・SQL
- APIレスポンス形式
- SESSION / Cookie
- JSON生成・参照先
- cron / CLI / batch
- メール送受信
- 影響範囲
- 既存テストまたは確認手段

## 実装前に決めること

- 対応目的
- 対象ファイル
- 変更しないファイル
- 仕様根拠
- 影響範囲
- ロールバック可能性
- 確認コマンド

## 実装後に確認すること

- `php -l` などの構文確認
- 必要に応じたAPI / CLI / DB確認
- Codexの採否判断をChatGPTでレビューしたか
- 修正後Claude再レビューが必要か
- 修正後Claude再レビューを実施した場合、その結果をChatGPTで整理したか
- 追加修正を行った場合、構文確認、必要なテスト、git diff再確認を行ったか
- 仕様書との整合
- 旧パス、旧仕様、未使用コードを誤って参照していないか
- git diffで依頼外変更がないか

## 禁止事項

- 調査依頼だけでコード編集する
- Claude指摘を事実確認せず直接実装する
- Claude修正後再レビューの結果を、ChatGPT整理とCodex事実確認なしに直接実装する
- ChatGPTの判断だけでコード変更する
- 本番DB、cron、`.procmailrc` を明示指示なしに変更する
- 実コードを整理目的だけで移動する

# Claude第三者レビューフロー

## 目的

Claudeを実装者ではなく、独立した第三者レビュワーとして利用するための工程です。

## 基本方針

- Claudeにはコード実装を依頼しない
- Claudeの指摘は確認候補として扱う
- 指摘は、Codexが実リポジトリで事実確認してから採否判断する
- 確定仕様、既存コード、DB仕様をClaude回答より優先する
- 大規模リファクタリング提案は、そのまま採用しない

## レビュー種別

Claudeレビューは、初回第三者レビューと修正後再レビューを分けて扱います。

| 種別 | 目的 | 確認範囲 |
| --- | --- | --- |
| 初回第三者レビュー | Codexの初回実装に対する第三者確認 | 仕様矛盾、既存処理への影響、セキュリティ、SQL / DB、API、SESSION、CSRF、メール、CLI / cron、テスト不足 |
| 修正後再レビュー | Codexが採用項目を修正した後の再確認 | 前回指摘、Codex採否、採用項目、修正内容、修正後diff、構文確認・テスト結果 |

修正後再レビューは、新しい全面設計レビューではありません。

## レビュー依頼前に準備するもの

- 変更目的
- 対象機能
- 対象ファイル
- 確定仕様書
- Codexによる調査結果
- Codexによる実装概要
- git diff要約
- 特に確認してほしい観点
- 変更していない範囲

テンプレートは `../review/CLAUDE_REVIEW_REQUEST.md` を使用します。

## 修正後再レビュー依頼前に追加で準備するもの

- 初回Claudeレビューの指摘
- ChatGPTによる指摘整理
- Codexによる事実確認
- Codexの採用 / 保留 / 対応不要判断
- 採用した指摘
- Codexの修正内容
- 修正後git diff
- 構文確認・テスト結果

## Claudeに確認してほしい観点

- 仕様との矛盾
- 既存処理への影響
- セキュリティ
- SQL / DB整合性
- APIレスポンス
- SESSION / CSRF / 認可
- メール送受信
- CLI / cron
- エラーハンドリング
- テスト不足

修正後再レビューでは、前回指摘が正しく解消されたか、採用項目の修正で新しい不具合を入れていないかを中心に確認します。

## Claudeに依頼しないこと

- 実装の全面設計変更
- 既存構成を壊すリファクタリング
- DB構造変更の即時提案
- 仕様書にない機能追加
- 本番環境の操作
- 修正後再レビューで、前回指摘や修正後diffと無関係な新規設計レビューを行うこと

## レビュー後

Claude回答は `claude-to-codex-review-fix-flow.md` に従って整理します。

レビュー指摘を直接コードへ反映せず、REVIEW_FIX_TRACKERで妥当性確認と対応状況を管理します。

コメント、typo、文言、ドキュメントのみで挙動に影響しない修正は、理由を残したうえで修正後再レビューを省略できます。

PHPロジック、SQL / DB、認証、認可、SESSION、CSRF、API、メール、cron / CLI、個人情報、token、ファイル操作、JSON生成、複数ファイル、セキュリティに関わる修正では、原則として修正後再レビューを実施します。

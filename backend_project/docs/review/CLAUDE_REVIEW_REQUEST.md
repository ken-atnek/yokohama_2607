# Claudeバックエンドレビュー依頼テンプレート

## 依頼内容

以下の公開サイト連携バックエンド変更について、第三者レビューをしてください。

コード実装や大規模な設計変更は行わず、問題点、根拠、確認すべき事項を中心に指摘してください。

## レビュー種別

```text
初回第三者レビュー / 修正後再レビュー のどちらかを書く
```

修正後再レビューの場合は、前回指摘、Codex採否、採用項目、修正内容、修正後diff、構文確認・テスト結果の範囲に限定して確認してください。新しい全面設計レビューは行わないでください。

## 前提

- 対象は横浜ダンディーグループの公開サイト連携バックエンドです
- Next.js公開サイトから利用するPHP API / CLI / cron / メール / DB連携が主対象です
- 既存構造と確定仕様を優先します
- Claudeの指摘は実装指示ではなく、Codexが実リポジトリで確認する候補として扱います
- 大規模リファクタリングや仕様追加は提案しないでください
- 修正後再レビューの新規指摘も、ChatGPT整理とCodex事実確認を経てから採否判断します

## 特に確認してほしい点

- 仕様書との矛盾
- 既存処理への影響
- SQL / DB整合性
- 認証・認可・SESSION・CSRF
- APIレスポンスとHTTPステータス
- メール送受信
- CLI / cron
- エラーハンドリング
- テスト不足

修正後再レビューでは、以下を中心に確認してください。

- 採用した指摘が正しく解消されているか
- 保留 / 対応不要とした項目に、明らかな重大見落としがないか
- 修正後diffで新しい不具合を入れていないか
- 実施した構文確認・テスト結果と矛盾がないか

| --- | --- | --- | --- | --- | --- |
| 高/中/低 |  |  |  |  | 採用候補/保留候補/対応不要候補 |

## 禁止事項

- Claude回答のみを根拠にコード変更を指示しない
- 確定仕様よりClaude提案を優先しない
- 依頼範囲外の大規模リファクタリングを提案しない
- 本番DB、本番サーバー、cron、`.procmailrc` の直接変更を提案しない
- 修正後再レビューで、前回指摘や修正後diffと無関係な設計変更を要求しない
